# RED GREEN REFACTOR

## 快速规则

先确认当前任务的输入、revision、允许范围和停止条件。机器字段和参数边界统一见 [机器字段与状态边界](../core/machine-boundaries.md)。

## 详细规则

## 1. RED validity

先写或修改目标测试，再运行最小相关范围。有效 RED 必须因目标行为缺失或 BUG 仍存在而失败，不能是导入/编译错误、环境故障、fixture/Mock 配置错误或反向断言；失败信息应能定位预期行为。BUG 回归必须复现原始症状。记录命令、revision、时间和关键失败摘要。

禁止为了制造 RED 临时破坏正确代码。在看到有效 RED 前不实现对应新行为。纯重构例外：先保存当前 GREEN 表征基线。

## 2. GREEN

只实现使当前失败测试通过的最小正确业务行为，执行相关测试并保持既有行为通过；不得借 GREEN 扩大需求范围或顺带重写无关模块。

## 3. REFACTOR

在 GREEN 保护下拆职责、去重复、改命名、缩短方法并降低嵌套/复杂度。每组结构调整后重跑相关测试，再执行项目已配置的覆盖率/复杂度 Harness。若重构改变公共契约、调用边界或业务行为，必须返回契约与测试矩阵重新确认，不能把行为变化伪装成重构。

## 4. Regression truth

BUG 回归至少证明：修复前失败；失败原因与原始症状一致；修复后通过；相关回归仍通过；测试不依赖修复实现细节。只在修复后新增一个始终通过的测试，不构成回归保护。
