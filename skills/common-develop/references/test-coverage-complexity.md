# Test Coverage and Complexity

## 1. Interpretation

覆盖率只是发现未执行路径的诊断信号，不等于正确性。优先检查分支、条件、状态转换和高风险路径；异常用例完整性以实现契约和测试矩阵为准，不能仅看报告百分比。复杂但未测试的分支即使总体覆盖率达到阈值也会阻塞完成。

## 2. Project authority

真实阈值和命令只从项目 `harness_env.md` / CI 配置读取。项目尚未确认阈值时，可由 ProjectManagerAgent 协调以下渐进建议，但在写入项目环境文档前不得作为强制门禁：新增/修改方法圈复杂度建议 ≤10，嵌套层级建议 ≤3，普通新增业务代码分支覆盖建议 ≥80%，核心业务新增代码建议 ≥90%。

## 3. Gate

先对新增/修改范围生成报告，再基于历史代码建立基线；确认后的阈值才升级为 Harness 门禁。超过复杂度阈值应优先拆职责、提取策略或简化条件，不得靠增加测试数量掩盖难以 Review 的实现。
