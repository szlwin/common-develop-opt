# Test Seam

## 1. Highest stable seam

优先验证调用者可观察的公共行为，按能覆盖目标规则的最高稳定 seam 选择：端到端业务入口 → API/应用服务 → 领域公共接口 → 数据访问边界 → 仅在确实独立稳定时测试更小单元。好的测试应在内部实现重写后仍成立。

## 2. Test-double boundary

只在时间、随机数、网络、文件、数据库、消息、缓存或明确外部协作端口等真实边界使用 Test Double。禁止 Mock 被测对象自身内部方法、用反射调用 private 方法、为测试暴露内部实现、增加 test-only 生产分支，或在 fixture 中复制业务逻辑。

数据映射、事务、参数绑定、序列化和其它依赖真实运行时的行为必须使用对应集成/契约测试，不能由纯替身测试代替。

## 3. Assertions and traceability

测试至少断言结果、异常、状态或边界副作用之一；异常场景断言稳定异常类型/业务错误码，并验证不应发生的写入、事件、状态变化或外部调用。关联影响按目标对象最终状态断言；跨模块场景使用 correlation/trace ID 核对状态和补偿证据。

测试名或显示名必须可映射 Case ID；同类输入优先参数化，复杂场景按业务状态分组。不要为覆盖率编写没有业务断言的测试。
