# HTML 生成核心规范

## 1. Source Rule

### 来源规则

从当前权威 Markdown 或结构化事实生成 HTML。HTML 只是只读展示，永远不能成为事实来源。

## 2. Output Rule

### 输出规则

生成确定性、自包含的输出，包含稳定标题、导航、可读表格和清晰的源 revision 元数据。

## 3. Command Semantics

### 命令语义

`wk -l` 渲染已经解析的项目、Feature 或 Bug 目标。它的 `-b/-f` 选择器只接受 ID，不得分类或创建请求。

写入前预览选定的输入和输出路径。不要覆盖权威 Markdown 或结构化文档。

## 4. Page Structure

### 页面结构

使用一个清晰的文档标题、元数据摘要、目录、语义化章节和稳定锚点。除非渲染契约规定了其他顺序，否则保持源文档顺序。

## 5. Accessibility

### 可访问性

使用语义化元素、可通过键盘访问的导航、有意义的链接文本、可读的对比度、表头，以及为信息性图片或图表提供文字替代。

## 6. Project Process HTML

### 项目流程 HTML

展示生命周期状态、当前阶段、已完成和已跳过阶段、阻断项以及源链接，但不要复制私有 Evidence 正文或完整操作历史。

## 7. Test Case HTML

### 测试用例 HTML

渲染测试 ID、相关验收规则、前置条件、步骤、预期结果、状态和证据引用。不要将密钥和原始环境凭据放入页面。

## 8. Bug Report HTML

### Bug 报告 HTML

渲染 Bug ID、描述、复现方式、预期和实际行为、影响、受影响 revision、状态和证据引用。不要将 Bug 重新解释为 Feature 请求。
